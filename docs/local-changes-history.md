## 维护规则

1. 新增本地非 merge 提交后追加或重新生成快照，并更新总数和 `snapshot_head`；总数只计算当前 HEAD 可达的按月主表，旧分支补遗和 merge 索引不计入。
2. 每次上游合并后，先更新当前功能正文，再检查历史行是否应从 `active` 调整为 `superseded`、`reverted` 或 `merge-adaptation`。
3. merge commit 的完整过程进入单次上游合并记录；本附录可保留旧 merge 的来源索引，但不纳入非 merge 主表。merge 后的本地修复/适配 commit 仍进入主表。
4. 不按 commit 标题把官方上游功能算成本地功能；作者、父子关系、路径和当前代码入口必须共同判断。
5. 若作者身份新增，先由用户确认再扩大统计口径，避免把上游贡献者误算为本地提交。
